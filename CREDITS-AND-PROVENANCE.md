Software Planning Lead V5.6.1 is an independently written first-party planning/autonomous-delivery methodology. External skills, repositories, documentation and standards are **research inputs**, not vendored runtime dependencies or text templates.

## Adaptation rule

External skill bodies are not copied into this library. Review useful concepts, verify drift-sensitive claims against authoritative sources, extract the durable engineering decision/failure model, and rewrite it in CtrlAltDelegate's own portable terminology. Do not inherit source-specific harness assumptions, mandatory libraries, branding, arbitrary thresholds or vendor preferences unless the target project itself requires them.

## Maintenance rules

- Re-research drift-prone framework/tool/provider facts when they materially affect a decision.
- Keep global autonomy/routing/evidence policy in `docs/system/SKILL-EXECUTION-CONTRACT.md`; do not replicate it in specialist skills.
- Use progressive `references/` for deep/version-sensitive detail and load only the files required by the job.
- Record material source reviews in `.agents/skills/SOURCE-RESEARCH-MATRIX.yaml` with reviewed revisions where available.
- Never hardcode third-party Pi package versions or model choices into methodology.
- Release QA scans operative files/skills/bundles for stale version/path references, validates manifests/evals and proves canonical skill/adaptor parity.
- Library breadth is allowed, but new/retained skills must provide unique routable decision value. Merge or retire specialists that fail behavior/routing evaluation after global-policy extraction.
