# Skill Coverage Audit — V5.6.4

V5.6.4 re-audited the V5.5 library against current ECC and Shokunin repositories plus project/vendor skill repositories discovered through officialskills.sh. The purpose is **gap detection and expert-depth comparison**, not mirroring any external catalog.

## Classification

Every candidate concept is classified before adoption:

- **MERGE** — strengthens an existing first-party specialist or progressive reference.
- **SYSTEM** — belongs in global execution/routing/governance, not a project-domain skill.
- **NEW** — distinct recurring decisions/failure modes/verification justify a new routable specialist.
- **DEFER** — plausible specialist but current evidence does not justify separate routing/context cost.
- **REJECT** — redundant, overly vendor-prescriptive, stale, unsafe or not relevant to this methodology.

## V5.6.4 outcomes

- 139 existing canonical skills retained for post-refactor behavior evaluation; no skill was deleted merely because its V5.5 body contained duplicated governance.
- Six new specialists added: MongoDB, Terraform, Cloudflare platform, WordPress, threat modeling and property-based testing.
- All framework-stack specialists plus React Native/Flutter were moved from generic process framing toward framework-specific decision/failure/verification guidance.
- V5.6.4 structurally audited all 145 skills and substantively completed 59 entrypoints left with heading-only/generic migration remnants; each now has domain-specific context/invariants/failure/drift/verification guidance plus a progressive decision playbook.
- Cross-cutting PostgreSQL, GraphQL, security, auth, testing, web performance and accessibility depth was expanded.
- 136 progressive reference files hold deeper material without forcing every worker to ingest it.
- Generic IaC remains an umbrella; Terraform receives its own specialist because state-address/refactor semantics materially change safe execution.

## Retention/pruning rule

145 is a release observation, not a target. After global policy is removed, each skill must prove unique decision value through routing/behavior evaluation. Merge or retire a skill if its presence does not materially improve a realistic bounded task over the global contract plus adjacent specialists.

## Domains intentionally handled by research first

Legal/compliance, clinical/medical, investment/trading, narrow vendor APIs and similarly high-stakes or fast-moving domains are not automatically converted into large static skills. Use current authoritative research and create a project-specific specialist only when a stable engineering responsibility and verification contract emerge.
