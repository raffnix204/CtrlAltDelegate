# Documentation Governance — Deep Reference
## When to read this reference

Read this reference when **field guide** is material to the current documentation engineering decision, failure path, compatibility question or verification plan. Do not preload it for unrelated jobs.

Assign four non-overlapping roles where useful:
- Constitution/instructions: rules contributors/agents must obey.
- Map: architecture/navigation/ownership.
- Status: current health/blockers/intentional removals.
- History: durable decisions/migrations/incidents.

Reuse the repository's existing documentation structure instead of creating four new root files. One canonical owner per durable fact; other docs link.
